# CARD 03 — DETAILED SCREEN & PAGE WIREFRAME SPECIFICATION

## Mục tiêu

Triển khai cấu trúc và interaction chi tiết cho các page P0 dựa trên design foundation. Có thể dùng mock data trong phase UI, nhưng mock phải được đánh dấu rõ và component contract phải sẵn để nối API thật.

## Routes chốt

```text
/overview
/market
/market/watchlist
/trading/:symbol
/portfolio
/history
/simulation
/simulation/trading/:symbol
/simulation/portfolio
/simulation/history
/settings
```

Auth routes nằm ở card 01/08.

## 1. Tổng quan `/overview`

Blocks theo thứ tự ưu tiên:

1. account summary: tổng tài sản, sức mua/cash, market value, today P/L;
2. VNINDEX/HNXINDEX/UPCOMINDEX cards;
3. holdings preview;
4. performance chart;
5. recent activity/orders/fills.

Requirements:

- account type/mode phải visible;
- no-data portfolio có CTA sang Market/Simulation;
- index cards không dùng hardcoded live state;
- skeleton giữ dimensions để page không shift.

## 2. Thị trường `/market`

### Secondary nav

`Cổ phiếu | Watchlist | Chỉ số | Ngành`

P0 core là Cổ phiếu + Watchlist + indices. Industry tab có thể placeholder/limited nếu data P0 chưa đủ, không giả dữ liệu.

### Filters/sorts

Exchange:

`Tất cả | HSX/HOSE | HNX | UPCOM`

Sort options:

- Vốn hóa;
- Thanh khoản;
- Tăng;
- Giảm;
- NN mua ròng nếu provider trả field;
- A-Z.

Page sizes: 20/50/100.

### Desktop market table MVP columns

- watch star;
- mã;
- tên công ty nếu đủ chỗ;
- sàn;
- giá;
- thay đổi;
- %;
- vốn hóa;
- Giá trị GD;
- khối lượng;
- optional sparkline khi backend contract support.

Row click → `/trading/:symbol`.
Star click chỉ toggle watchlist, **không route**.

Market list sort/filter server-side; không download toàn market rồi sort client.

## 3. Giao dịch `/trading/:symbol`

Đây là workspace sâu nhất.

### Header instrument

Hiển thị:

- symbol + company;
- exchange;
- last price;
- change/%;
- reference/ceiling/floor;
- trading/session status;
- LIVE/stale/reconnecting/provider-mode indicator.

### Main desktop layout

```text
[ contextual watchlist ] [ chart + stock context ] [ order panel ]
                       [ bottom data panel spans center/right ]
```

Context watchlist không phải permanent global sidebar.

### Chart

P0 intervals:

- 5m;
- 15m;
- 1H;
- 1D.

Modes:

- Candlestick default;
- Line optional.

Có volume pane. Historical snapshot qua REST, current candle/quote patch realtime. Không refetch full series mỗi tick.

### Order panel

BUY/SELL tabs nằm trong panel.

P0 fields:

- side;
- order type = LO only;
- price;
- quantity;
- estimated value;
- available cash hoặc available shares;
- validation hints;
- submit CTA.

Submit luôn qua confirmation modal. Modal nhắc symbol/side/qty/limit price/account mode. Không show “execution price guaranteed”.

NORMAL mode:

- panel vẫn render;
- broker status `Chưa kết nối`;
- submit disabled hoặc backend returns `BROKER_NOT_CONNECTED` với UX rõ.

SIMULATION mode:

- badge rõ;
- initial buying power 100M;
- notice không dùng tiền thật;
- same OrderForm component, khác account context.

### Bottom tabs

Tối thiểu:

- bid/ask/current market summary;
- lệnh đang chờ;
- danh mục liên quan;
- khớp lệnh/fills.

Không claim full level-2 orderbook nếu provider/contract không có.

## 4. Danh mục `/portfolio`

Context tabs:

`Tổng quan | Nắm giữ | Hiệu suất | Phân bổ`

Summary:

- cash/sức mua;
- market value;
- equity;
- unrealized P/L.

Holdings table:

- symbol;
- quantity;
- available/reserved where useful;
- average cost;
- current;
- market value;
- unrealized P/L;
- weight.

Quote updates patch current/market value/P&L realtime; backend snapshot vẫn authority.

## 5. Lịch sử `/history`

Phân biệt rõ:

- orders/intents;
- fills/executions.

Filters:

- BUY/SELL;
- symbol;
- status;
- date range;
- account mode nếu page có cross-mode view hợp lệ.

Statuses UI cần map ít nhất:

- FILLED = Đã khớp;
- PENDING = Chờ khớp;
- PARTIALLY_FILLED = Khớp một phần (domain/future; không cần engine P0);
- CANCELLED = Đã hủy;
- REJECTED = Từ chối.

Order row click mở detail drawer/modal; không biến bảng thành trang quá rộng.

## 6. Giả lập `/simulation`

Simulation overview:

- virtual equity;
- virtual cash/sức mua;
- return %;
- holdings;
- performance;
- recent orders/fills;
- CTA `Giao dịch giả lập`.

Reset action là destructive action:

- không đặt cạnh primary buy/sell CTA dễ bấm nhầm;
- confirmation nêu rõ xóa simulation state;
- sau reset = cash/equity 100M, no positions, no pending orders.

Subroutes reuse portfolio/trading/history components với simulation account context.

## 7. Global search behavior

Dropdown keyboard:

- ArrowDown/ArrowUp chọn item;
- Enter mở;
- Escape đóng;
- focus/aria semantics hợp lý.

Debounce network request. Click FPT mở Trading FPT.

## 8. Market session UX

Header/order panel có human label từ backend state, ví dụ:

- Trước phiên;
- ATO;
- Đang giao dịch;
- Nghỉ trưa;
- ATC;
- Sau phiên;
- Đóng cửa.

Order controls disable dựa trên capability/backend rule, không hardcode clock độc lập ở frontend làm authority.

## 9. Realtime cell behavior

Khi quote thay đổi:

- update số liệu ngay;
- optional flash background khoảng 300–500ms;
- không animation dài;
- không rerender toàn table;
- stale data bỏ LIVE indicator.

## 10. Responsive detail

### Tablet 768–1024

- chart/order panel có thể stack hoặc drawer;
- hide low-priority market columns;
- context watchlist collapsible.

### Mobile

Bottom nav ưu tiên:

`Tổng quan | Thị trường | Giao dịch | Danh mục | Giả lập`

- market table → compact row/card;
- order form → BottomSheet;
- chart giữ usable height;
- simulation badge luôn visible;
- destructive reset vẫn khó bấm nhầm.

## Data/API dependencies

Card này phụ thuộc contracts từ card 05/08, nhưng UI layer không import vendor shape. Dùng normalized types `Quote`, `MarketIndex`, `Position`, `Order`, `Fill`.

Trong phase mock UI, tạo fixture gần đúng normalized DTO; không tạo một shape riêng sau này phải rewrite component.

## Testing

- route smoke tests;
- market row click vs watchlist star click;
- keyboard search;
- order confirmation contents;
- NORMAL broker-not-connected state;
- SIMULATION badge + cash label;
- history filters;
- reset confirmation;
- realtime cell update without full page replacement;
- mobile order BottomSheet.

## Critical acceptance journey

User có thể:

1. mở app;
2. thấy indices;
3. vào Thị trường;
4. tìm FPT;
5. mở FPT + chart;
6. add/remove watchlist;
7. vào Simulation thấy 100M;
8. BUY FPT;
9. thấy position/P&L;
10. SELL FPT;
11. thấy order/fill history;
12. reset Simulation.

Trong journey không được có điểm nào khiến user tưởng Simulation = Main hoặc mock feed = real live feed.

## Không được làm

- Không đưa feature P1 vào screen chỉ để lấp chỗ trống.
- Không fake level-2 bid/ask/depth.
- Không duplicate TradingPage riêng hoàn toàn cho Simulation.
- Không hardcode market session theo client clock làm authority.
