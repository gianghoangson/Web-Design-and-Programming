# CARD 06 — TRADING & SIMULATION BUSINESS LOGIC SPECIFICATION

## Mục tiêu

Implement `MarketRuleEngine`, `TradingService`, reservation logic và `SimulationExecutor` đủ đúng cho paper trading Vietnam P0, với dữ liệu market thật hoặc mock-normalized nhưng không đơn giản hóa sai các invariant tài chính.

## 6 rules không được vi phạm

1. Backend là source of truth.
2. Displayed quote không bảo đảm execution price; backend lấy latest quote khi xử lý.
3. Rules exchange/session/tick/lot phải centralized/config-driven.
4. Simulation/Broker dùng cùng trading interface.
5. Stale/unavailable market data không được dùng để fill Simulation.
6. Order/fill/cash/position/ledger thay đổi atomically.

## MarketRuleEngine

Interface/responsibility:

- resolve exchange session;
- allowed order types by exchange/session;
- validate security trading status;
- validate lot size;
- validate tick size;
- validate price floor/ceiling;
- validate optional max quantity;
- return machine-readable error code.

Không rải `if HOSE...` trong controllers/components.

## Session baseline

Config phải có khả năng represent:

### HOSE

- 09:00–09:15 opening auction: LO/ATO domain;
- 09:15–11:30 continuous: LO/MTL domain;
- lunch break;
- 13:00–14:30 continuous;
- 14:30–14:45 ATC: LO/ATC domain.

### HNX

- continuous sessions với LO/MTL/MOK/MAK domain;
- ATC;
- post-close PLO domain.

### UPCOM

- continuous trading; P0 LO.

**P0 executor/UI chỉ LO** dù engine/config có thể model các future types.

Normalized market session state có thể dùng:

`PRE_OPEN, ATO, CONTINUOUS_AM, LUNCH_BREAK, CONTINUOUS_PM, ATC, POST_CLOSE, CLOSED`.

Provider status/session ưu tiên hơn client/server clock; clock chỉ fallback.

## Price representation

All validation values full VND/share.

Example FPT:

- `128500` nghĩa 128,500 VND/share.
- UI `128.50` nếu chọn convention hiển thị vẫn submit `128500`.

## Tick-size baseline

Config/test baseline:

### HOSE

- price < 10,000 → tick 10 VND;
- 10,000 đến 49,950 → tick 50 VND;
- >= 50,000 → tick 100 VND.

### HNX/UPCOM

- tick 100 VND baseline P0.

Tests bắt buộc gồm:

- HOSE `128500` valid;
- HOSE `128550` invalid;
- HNX `27300` valid;
- HNX `27350` invalid.

Nếu current official/provider rules thay đổi, config có thể update; không hardwire spread logic khắp app.

## Price band

Validate limit price:

```text
floorPrice <= price <= ceilingPrice
```

`referencePrice`, `ceilingPrice`, `floorPrice` lấy normalized market quote/provider làm authority. Không tự tính ±7/10/15 làm source of truth vì có special cases.

## Lot rule

P0:

```text
quantity > 0
quantity % 100 == 0
```

Odd lot P1. Max order quantity nếu có là config.

## Security status

Trading allowed only khi normalized security status/rule cho phép. `SUSPENDED` reject `SECURITY_SUSPENDED`.

## Buying power & reservations

Account fields:

```text
cashBalance
availableCash
reservedCash
```

Pending BUY LO:

- reserve required cash;
- reduce available cash accordingly;
- do not debit final cash as filled trade until execution, theo accounting model chọn nhất quán;
- cancel releases reserve.

BUSINESS invariant: user không thể submit hai pending/concurrent orders vượt available buying power.

## Sellable quantity

Position fields:

```text
quantity
availableQuantity
reservedQuantity
```

Pending SELL:

- reserve shares;
- reduce available quantity;
- cancel release;
- no short.

## Order lifecycle P0

Có thể internally:

```text
CREATED -> VALIDATED -> SUBMITTED -> PENDING -> FILLED
                                      |          
                                      -> CANCELLED
VALIDATION FAILURE -> REJECTED
```

Domain hỗ trợ `PARTIALLY_FILLED` future, nhưng P0 matcher không cần generate partial fills.

## LO execution model P0

### BUY

Marketable nếu:

```text
ask1 != null && ask1 <= limitPrice
```

Execution price = current ask1 (price improvement allowed).

Nếu ask > limit → PENDING.

### SELL

Marketable nếu:

```text
bid1 != null && bid1 >= limitPrice
```

Execution price = current bid1.

Nếu bid < limit → PENDING.

### Last-price fallback

Không fallback silently. Nếu MockProvider/test mode cần fallback, expose explicit config/strategy. UI/dev docs phải nói feed limitation.

## Pending matcher

Khi quote update cho symbol:

1. ignore stale/out-of-order quote;
2. find PENDING Simulation LO relevant symbol;
3. evaluate eligibility;
4. process each with locking/idempotent status check;
5. fill atomically;
6. emit `order:update`, `fill:new`, `portfolio:update`.

Không scan toàn orders table mỗi tick. Query/index theo status+security/account phù hợp.

## Cancel

Only order PENDING (và PARTIALLY_FILLED future) cancellable.

Transaction:

- lock/re-read order;
- ensure still pending;
- set CANCELLED;
- release cash/share reservation;
- commit;
- emit order/portfolio updates.

Modify order P0 = cancel + submit new order; không implement complex amendment.

## Stale quote

Before any new order validation/fill:

```text
quoteAge <= ORDER_QUOTE_MAX_AGE_MS
```

Nếu quá ngưỡng:

`STALE_MARKET_DATA`.

Nếu no quote/provider down:

`MARKET_DATA_UNAVAILABLE`.

Session-aware: ngoài phiên, quote không update liên tục không đồng nghĩa “bad feed”; rule engine + provider session status quyết định UI/trading availability.

## Average cost

BUY:

```text
newQty = oldQty + fillQty
newAvg = (oldQty*oldAvg + fillQty*fillPrice) / newQty
```

SELL:

- quantity decreases;
- avg cost stays same for remaining units;
- realizedPnL pre-fee = `(fillPrice - avgCost) * sellQty`;
- position zero → remove row.

## FeeEngine

Create abstraction:

```ts
interface FeeEngine {
  calculateTradeFees(input): { commission; tax; totalFees }
}
```

P0 Basic Simulation may return 0 commission/tax. Không hardwire zero fee sâu trong execution accounting khiến sau này khó thay.

## Settlement

P0 = immediate settlement. Sau fill BUY shares available theo simplified model; SELL proceeds available theo simplified model. Full T+2 is excluded P0.

## TradingService required flow

1. authenticate;
2. load account + ownership;
3. load security;
4. validate market/session/order type;
5. latest normalized quote;
6. freshness;
7. quantity/lot/price/tick/band;
8. resource checks;
9. choose executor:
   - SIMULATION → `SimulationExecutor`;
   - NORMAL → `BrokerExecutor`;
10. executor response normalized.

`BrokerExecutor` P0 returns `BROKER_NOT_CONNECTED`; never creates fake fill.

## Atomic fill transaction

BUY fill transaction:

- lock account;
- lock/re-read order;
- ensure not already filled/cancelled;
- calculate fees;
- create fill;
- debit/release cash reservation;
- upsert position and avg cost;
- write ledger;
- mark order FILLED;
- commit.

SELL analogous with locked position and cash credit.

If any step fails, rollback all.

## Idempotency & concurrency

Order submit idempotency key stored/checked at DB/service level.

Concurrent scenarios tests:

- cash 10M; two BUY 8M each → max one succeeds/reserves;
- shares 100; two SELL 100 each → max one succeeds/reserves;
- matcher/cancel race → exactly one terminal outcome, no double release/fill.

## Reset Simulation

Atomic procedure:

- verify Simulation ownership;
- cancel pending;
- clear reservations;
- clear simulation positions/fills/orders/history according reset policy;
- reset account 100M;
- reset snapshots/performance;
- ledger/audit reset entry if retained;
- emit portfolio/account update.

After reset:

```text
cash=100000000
equity=100000000
positions=[]
pendingOrders=[]
returnPercent=0
```

NORMAL unchanged.

`INVALID_QUANTITY`, `INVALID_LOT_SIZE`, `INVALID_PRICE`, `INVALID_PRICE_TICK`, `PRICE_ABOVE_CEILING`, `PRICE_BELOW_FLOOR`, `INVALID_ORDER_TYPE`, `MARKET_CLOSED`, `INVALID_SESSION`, `INSUFFICIENT_BUYING_POWER`, `INSUFFICIENT_POSITION`, `STALE_MARKET_DATA`, `MARKET_DATA_UNAVAILABLE`, `SECURITY_SUSPENDED`, `ORDER_ALREADY_FILLED`, `ORDER_NOT_CANCELLABLE`.

## Acceptance journey

With deterministic FPT quote fixture:

1. Simulation has 100M;
2. submit BUY 100 FPT LO;
3. if ask <= limit → FILLED at ask; else PENDING with reserve;
4. qualifying quote fills pending;
5. cash/position/ledger/history correct;
6. quote moves → uPnL correct;
7. SELL at bid logic;
8. realized outcome/history correct;
9. reset to 100M clean state.

## Không được làm

- Không use last price when bid/ask available.
- Không accept stale quote “vì simulation thôi”.
- Không hardcode market rules ở UI.
- Không let cash/position update outside transaction.
- Không implement broker P0.
