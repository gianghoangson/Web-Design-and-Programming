# CARD 05 — API & WEBSOCKET SPECIFICATION

## Mục tiêu

Implement backend contract giữa frontend và core services theo `REST API + WebSocket`, version `/api/v1`. Frontend không được biết provider/broker-specific payload.

## Architectural boundary

Backend phục vụ 4 nhóm:

1. Application API — user/account/portfolio/history/watchlist.
2. Market Data API — securities/indices/quote/candles/session.
3. Realtime Gateway — quote/index/candle/order/fill/portfolio/market status.
4. Trading Gateway — `TradingService` route Simulation/Broker executor.

## Standard response envelope

Success:

```json
{ "success": true, "data": {} }
```

List:

```json
{
  "success": true,
  "data": [],
  "meta": { "page": 1, "pageSize": 50, "total": 312, "totalPages": 7 }
}
```

Error:

```json
{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_BUYING_POWER",
    "message": "Không đủ sức mua.",
    "details": {},
    "requestId": "optional-correlation-id"
  }
}
```

Frontend phải branch theo stable `error.code`, không parse message string.

## Auth

Private endpoint dùng bearer access token hoặc auth strategy hiện có tương đương, nhưng contract security phải rõ.

P0 endpoints:

```text
POST /api/v1/auth/register
POST /api/v1/auth/login
GET  /api/v1/auth/me
```

Không leak password hash/token trong logs/responses.

## Accounts

```text
GET /api/v1/accounts
GET /api/v1/accounts/:accountId
```

Mọi account endpoint check ownership server-side. Cross-user ID → `403 ACCOUNT_ACCESS_DENIED`.

Account DTO expose đủ:

- id;
- name;
- type;
- cashBalance;
- availableCash;
- reservedCash;
- startingBalance khi simulation;
- derived marketValue/equity nếu endpoint detail phục vụ UI.

## Optional dashboard aggregate

Nếu frontend cần tránh 10–15 call:

```text
GET /api/v1/dashboard?accountId=<id>
```

Có thể aggregate account summary/positions/recent activity. Indices vẫn có Market API/WS. Không bắt buộc nếu current architecture làm parallel queries hiệu quả, nhưng đừng tạo waterfall network.

## Market API

```text
GET /api/v1/market/search?q=FPT
GET /api/v1/market/securities
GET /api/v1/market/securities/:symbol
GET /api/v1/market/securities/:symbol/quote
GET /api/v1/market/securities/:symbol/candles
GET /api/v1/market/indices
GET /api/v1/market/session
```

### Search

Return normalized:

```json
{
  "securityId": "uuid",
  "symbol": "FPT",
  "companyName": "CTCP FPT",
  "exchange": "HOSE"
}
```

### Security detail

Master data only. Current quote không cần nhét vào security entity.

### Quote

DTO normalized fields tối thiểu:

```ts
interface Quote {
  symbol: string;
  referencePrice: number|string;
  ceilingPrice: number|string;
  floorPrice: number|string;
  lastPrice: number|string|null;
  bidPrice: number|string|null;
  askPrice: number|string|null;
  change: number|string|null;
  changePercent: number|null;
  open: number|string|null;
  high: number|string|null;
  low: number|string|null;
  volume: number|string|null;
  tradingValue: number|string|null;
  session?: string;
  tradingStatus?: string;
  timestamp: string;
}
```

Use numeric serialization strategy consistent; all price values mean full VND/share.

REST quote dùng initial load/fallback/reconnect recovery; realtime qua WS.

### Market table

`GET /market/securities` parameters:

- `exchange`;
- `sort`;
- `direction`;
- `page`;
- `pageSize` (max 100).

Sort whitelist:

- `market_cap`;
- `trading_value`;
- `volume`;
- `change_percent`;
- `foreign_net_value` if available;
- `symbol`.

Không nối raw sort string vào SQL/provider query.

### Candles

Parameters:

- `interval=5m|15m|1h|1d` P0;
- `from`/`to` ISO timestamps.

Return OHLCV normalized.

## Watchlist API

```text
GET    /api/v1/watchlists
POST   /api/v1/watchlists/:id/items
DELETE /api/v1/watchlists/:id/items/:securityId
```

POST body:

```json
{ "securityId": "uuid" }
```

Ownership của watchlist phải check server-side.

## Portfolio API

```text
GET /api/v1/accounts/:accountId/portfolio
GET /api/v1/accounts/:accountId/performance?range=1D|1W|1M|3M|YTD|1Y
```

Portfolio response:

- summary cash/marketValue/equity/uPnL;
- positions with quantity/averageCost/currentPrice/marketValue/uPnL.

`currentPrice` ghép từ quote cache/service, không từ DB positions.

## Orders API

```text
POST /api/v1/accounts/:accountId/orders
GET  /api/v1/accounts/:accountId/orders
POST /api/v1/accounts/:accountId/orders/:orderId/cancel
```

Submit body P0:

```json
{
  "securityId": "uuid-fpt",
  "side": "BUY",
  "orderType": "LO",
  "quantity": 100,
  "price": 128500
}
```

Bắt buộc header:

```text
Idempotency-Key: <uuid>
```

Không có `executionPrice` trong request.

GET filters:

- side;
- status;
- symbol;
- from/to;
- page/pageSize.

Cancel:

- only pending/cancellable;
- check ownership;
- release reservations atomically.

## Fills API

```text
GET /api/v1/accounts/:accountId/fills
```

Fill DTO chứa orderId, symbol, side, qty, execution price, gross, commission, tax, executedAt.

## Simulation convenience API

```text
GET  /api/v1/simulation
POST /api/v1/simulation
POST /api/v1/simulation/:accountId/reset
```

Create/reset phải idempotent hợp lý. Reset semantics là action, không dùng DELETE.

Reset success trả cash `100000000`, empty positions, return 0.

## Market session API

`GET /api/v1/market/session`

Return normalized provider-aware state. UI map sang human labels; không dùng frontend local clock làm authority.

## WebSocket contract

Use Socket.IO semantics, event names:

### Client → server

```text
subscribe:quotes
unsubscribe:quotes
subscribe:indices
```

Payload supports arrays of symbols/codes.

### Server → client

```text
quote:update
index:update
candle:update
market:status
order:update
fill:new
portfolio:update
```

Optional envelope version:

```json
{ "v": 1, "event": "quote:update", "data": {} }
```

## Snapshot vs stream rule

Official pattern:

```text
page load -> REST current snapshot
          -> socket subscribe
          -> WS incremental updates
```

Do not wait for first tick to render quote. Do not send full 30-field quote every tick if only few fields changed.

## Subscription manager

Frontend set union của symbols từ:

- current market page;
- watchlist;
- portfolio;
- current chart/trading screen.

`FPT` xuất hiện 3 sources vẫn subscribe một lần. Chỉ unsubscribe provider/browser ref khi ref-count về 0.

## Reconnect lifecycle

```text
connect -> authenticate -> subscribe indices/account symbols/workspace
on disconnect -> reconnect -> authenticate -> rejoin/resubscribe -> REST refresh -> continue
```

Socket stale/disconnected state phải visible UI.

## Out-of-order/duplicate policy

Backend và/or frontend guard:

- timestamp cũ hơn latest known → ignore;
- same timestamp + same values → ignore;
- do not regress quote display.

## Stale policy

Config values đến từ environment; product default dev documented ở CODEX.

- warning → UI indicates stale/reconnecting;
- trading threshold exceeded → reject Simulation order.

## API security

- account ownership every private route;
- Zod validate body/query/params;
- rate limit login/search/order;
- order idempotency;
- request correlation ID;
- no secrets logs;
- no frontend-controlled execution/cash/position.

## Logging

Structured log fields có thể gồm:

- requestId;
- userId;
- accountId;
- endpoint;
- orderId;
- errorCode;
- latency.

Redact secrets.

- stale;
- out-of-order;

## Acceptance flow

API layer complete khi support:

`Login → Accounts → Market/Indices → Search FPT → Security/Quote/Candles → WS FPT → Simulation → BUY 100 → Order/Fill/Cash/Position → portfolio:update → price update → P/L change → SELL → History`.

## Không được làm

- Không expose SSI field names to frontend.
- Không one-WS-per-row.
- Không trust accountId.
- Không send executionPrice from UI.
- Không skip idempotency/concurrency vì “paper trading”.
