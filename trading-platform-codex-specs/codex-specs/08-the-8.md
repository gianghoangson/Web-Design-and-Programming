# DOCUMENT 06 — MVP TECHNICAL SPECIFICATION

## Mục tiêu end-to-end

MVP phải chạy được:

`Login → Overview → HOSE/HNX/UPCOM → Search FPT → Quote/Chart → Watchlist → Simulation 100M → BUY/SELL LO → Vietnam validation → pending/fill/cancel → cash/position/P&L realtime → orders/fills history → reset`.

# DOCUMENT 07 — MARKET DATA INTEGRATION SPECIFICATION

## Data needs P0

Need normalized access to:

- securities master;
- latest last price;
- reference/ceiling/floor;
- best bid/ask level 1;
- OHLCV/candles;
- VNINDEX/HNXINDEX/UPCOMINDEX;
- trading status/session.

## Provider strategy

### Primary real-provider target

`SSI FastConnect Data` is preferred integration target for MVP read-only market data, subject to account registration/approval/credentials/provider restrictions.

Do not block development on credentials. Always have:

- `MockMarketProvider` for dev/test;
- `SSIProvider` adapter for real P0 when available;
- `DNSEProvider`/other providers only as future adapters.

Only one real provider active at a time via factory/config.

## Browser boundary

Never:

```text
Browser -> SSI API
```

Always:

```text
Browser -> our Backend -> MarketDataProvider -> SSI/Mock/etc.
```

Reasons: secrets, normalization, caching, rate limiting, provider swap, licensing controls.

## Provider normalization

SSI/vendor raw names stay inside adapter. Conceptual feed sources can include session/status, quotes, trades, indices, OHLCV, but frontend only gets internal DTO.

Internal full-VND price always.

## Securities master sync

Do not query full securities master on every Market page request.

Implement sync strategy:

- startup sync;
- scheduled daily sync, e.g. morning Asia/Ho_Chi_Minh;
- UPSERT `securities`/exchange status;
- robust to provider partial failure.

## Quote initial load

`getQuote(symbol)` behavior:

1. if cache fresh enough → return cache;
2. if missing/stale and provider REST available → refresh;
3. store normalized result + timestamps;
4. return.

Frontend renders REST snapshot immediately then receives stream.

## Demand-based subscriptions

Do **not** subscribe ALL market symbols for every user.

Maintain backend/frontend needed symbol sets/ref-count.

Always-on indices:

- VNINDEX;
- HNXINDEX;
- UPCOMINDEX;
- optional VN30 future if UI needs.

Market page subscribes visible page (e.g. 50). On pagination/filter:

- remove unneeded page symbols;
- subscribe new symbols;
- retain watchlist/portfolio/current chart refs.

## Quote freshness

Cache each quote with:

- provider timestamp;
- backend `receivedAt`.

Use `receivedAt` for transport freshness; retain provider timestamp for ordering/audit.

Defaults:

```env
QUOTE_STALE_WARNING_MS=10000
ORDER_QUOTE_MAX_AGE_MS=15000
```

Session-aware logic required. Outside active session, low update frequency is expected.

## Trading session authority

Provider trading status/session wins when available. Clock fallback only if feed lacks status.

Frontend receives normalized market status, not independent schedule logic.

## Candles

Historical chart:

- REST fetch history;
- realtime update current candle;
- do not refetch full candle history each quote tick.

Cache historical ranges if useful but keep implementation simple.

## Bid/ask & simulator

P0 execution uses level-1:

- BUY → ask1;
- SELL → bid1.

No level-2/queue simulation.
No last-price substitution when bid/ask exists.

## Failure modes

### Provider REST down, stream alive

- keep stream/current cache;
- REST fallback may return latest cache with metadata;
- UI should not crash.

### Stream down, REST alive

- show reconnecting/stale warning;
- can refresh snapshots via REST;
- reconnect provider stream.

### REST + stream down

- `MARKET_DATA_UNAVAILABLE`;
- Simulation trading disabled/rejected;
- UI keeps last known values only with clearly stale/offline label.

## Provider reconnect

Recommended exponential backoff:

`1s → 2s → 4s → 8s → 15s max + jitter`.

On reconnect:

1. reauthenticate provider;
2. restore active subscriptions;
3. refresh important snapshots;
4. resume browser emissions.

## Browser reconnect

On Socket.IO reconnect:

- auth user;
- join account room;
- resubscribe symbols/indices;
- REST refresh current quote/portfolio as necessary.

## Ordering/dedup

Ignore:

- quote with timestamp older than cache;
- duplicate same timestamp + same values.

Do not let reconnect replay cause price UI to go backward.

## No market ticks in PostgreSQL

P0:

- securities master persists;
- transactional financial state persists;
- current quote cache in-memory;
- candle history via provider API;
- no table receiving every price tick.

## MockMarketProvider

Must remain part of codebase. Requirements:

- deterministic securities (include FPT/VCB/HPG etc.);
- deterministic indices;
- deterministic quote sequence sufficient to test flash/P&L/matcher, e.g. FPT price evolving `128500 -> 128600 -> 128500 -> 128700` while valid bid/ask accompany it;
- deterministic candles;
- ability to simulate stale/disconnect/provider error in tests.

When app runs mock mode, UI must show `DEMO/MOCK` or equivalent — **not LIVE real market**.

## Provider factory

Example responsibility:

```ts
createMarketDataProvider(config.marketProvider)
```

Returns `MockMarketProvider` or `SSIProvider`; other app services consume only interface.
