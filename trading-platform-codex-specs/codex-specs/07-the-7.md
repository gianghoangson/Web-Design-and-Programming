# CARD 07 — IMPLEMENTATION ROADMAP & DEVELOPMENT TASK SPECIFICATION

## Mục tiêu

Triển khai theo dependency order để không dựng UI/realtime/trading rối lẫn nhau. Ưu tiên correctness và testable vertical slices; không tối ưu premature.

## Final stack reminder

Frontend: React + Vite + TypeScript + React Router + TanStack Query + Zustand + Axios + Socket.IO Client + Lightweight Charts + Tailwind/CSS variables.

Backend: Express + TypeScript + Zod + PostgreSQL + Prisma + Socket.IO.

Testing: Vitest, RTL, Supertest, Playwright.

Quote cache P0 in-memory; Redis P1 only.

## Repo shape

Recommended:

```text
repo/
  frontend/
    src/
      components/
      pages/
      features/
      services/
      stores/
      types/
      utils/
      styles/
  backend/
    src/
```

Feature-oriented modules được ưu tiên hơn giant `controllers/`/`services/` folders không domain boundary.

## Dependency graph

```text
Foundation
  -> Design System/App Shell
  -> Static UI / normalized mocks
  -> DB schema
  -> Auth + Accounts
  -> Market master + provider abstraction
  -> Market REST
  -> Realtime
  -> Portfolio/Watchlist
  -> Rule Engine
  -> Simulation Executor
  -> Order UI integration
  -> Performance/Snapshots
  -> Simulation Reset
  -> Responsive/Failure UX
  -> Security/Testing
  -> Deployment
  -> Future Broker
```

## Phase 0 — Scaffold

Deliver:

- frontend Vite TS;
- backend Express TS;
- shared env convention;
- Postgres + Prisma;
- health endpoint;
- lint/format/typecheck/test scripts;
- Docker Compose local.

Gate: both apps boot; DB connection works; CI/local commands documented.

## Phase 1 — Design system + shell

Implement card 02 primitives/tokens, header/nav/index strip placeholders, responsive shell, common states.

Gate: no business API dependency needed; visual rules centralized.

## Phase 2 — Static UI with normalized mocks

Build pages in card 03 with fixture types that match final internal DTOs.

- Overview;
- Market;
- Trading;
- Portfolio;
- History;
- Simulation.

Do not make vendor-shaped mocks. Gate: navigation/critical layouts usable desktop/mobile.

## Phase 3 — Database + Auth + Accounts

Implement card 04 schema/migrations/seeds.

Register/login/me. Create/obtain NORMAL and SIMULATION accounts. Simulation initial 100M.

Gate: ownership tests pass; account isolation verified.

## Phase 4 — Market provider abstraction + REST

Implement:

- `MarketDataProvider`;
- `MockMarketProvider` first;
- normalized quote/index/security/candle models;
- quote cache;
- market endpoints.

Then add real provider adapter (SSI) only when credentials/permission available.

Gate: pages run end-to-end on mock without code changes elsewhere; provider swap factory works.

## Phase 5 — Realtime

Implement backend provider stream → cache → Socket.IO and frontend subscription manager.

Gate:

- indices + FPT update live in app;
- reconnect/resubscribe;
- duplicate/out-of-order handling;
- stale UI.

## Phase 6 — Portfolio + Watchlist

Implement watchlist persistence/API, portfolio snapshot response combining DB positions + quote cache, reactive holdings updates.

Gate: current quote changes P/L display without writing quote into positions.

## Phase 7 — Trading validators

**TDD mandatory.** Implement `MarketRuleEngine` tests before executor.

- lot;
- tick;
- price band;
- session;
- order-type capability;
- security status;
- stale quote;
- resources.

Gate: test matrix green.

## Phase 8 — Simulation engine

Implement:

- `TradingService`;
- `OrderExecutor`;
- `SimulationExecutor`;
- `BrokerExecutor` stub;
- pending LO + reservation;
- marketable fill bid/ask;
- cancel;
- matcher on quote updates;
- DB transactions/locks/idempotency;
- ledger/positions/avg cost.

Gate: concurrency/idempotency/rollback tests pass before UI order submit enabled.

## Phase 9 — Trading UI integration

Wire order panel to real API:

- confirmation;
- idempotency key;
- server error mapping;
- pending/cancel state;
- history/order events;
- NORMAL broker-not-connected;
- Simulation 100M.

Gate: critical BUY/SELL UI flow works.

## Phase 10 — Performance snapshots

Implement snapshot cadence/API for portfolio performance. Avoid tick-level DB writes.

Gate: performance chart gets real snapshot series; empty state works.

## Phase 11 — Simulation overview/reset

Implement reset endpoint + UI destructive confirmation + refresh/invalidation/socket state.

Gate: reset exact 100M and no leakage to NORMAL.

## Phase 12 — Responsive pass

Target desktop/tablet/mobile per card 03. Mobile bottom nav/order sheet, table simplification.

Gate: Playwright viewport smoke tests.

## Phase 13 — Failure/degradation

Test and polish:

- provider REST down;
- provider stream down;
- both down;
- stale quote;
- socket reconnect;
- unauthorized account;
- backend 422/503;
- empty portfolio/watchlist.

No blank white page/full crash.

## Phase 14 — Testing pass

Run full suites; add missing cases from CODEX. Critical Playwright journey.

## Phase 15 — Security

- auth hardening;
- IDOR tests;
- Zod on all inputs;
- rate limits;
- secrets redaction;
- CORS/security headers per deployment;
- sort whitelist;
- request IDs.

Gate: cross-user account access always fails 403.

## Phase 16 — Performance optimization

Only after correctness:

- profile market table rerenders;
- batch subscriptions;
- cache query invalidation;
- API N+1 review;
- DB indexes/explain for order/history queries;
- chart update efficiency.

Không add Redis trừ khi multi-instance need proven.

## Phase 17 — Deploy/operability

- production env validation;
- Docker build;
- DB migration deployment;
- health/readiness;
- structured logs;
- CI tests/typecheck/build;
- README setup;
- market provider credentials backend-only.

## Rough sprint grouping

## Quality gates

### Gate A — Architecture

- no forbidden stack drift;
- provider/executor abstractions intact.

### Gate B — Data integrity

- Decimal money;
- DB transactions;
- account isolation;
- ownership.

### Gate C — Trading correctness

- rule engine tests;
- bid/ask execution;
- pending/cancel;
- idempotency/concurrency.

### Gate D — Realtime correctness

- reconnect;
- stale handling;
- duplicate/out-of-order;
- no fake LIVE.

### Gate E — UX

- Vietnamese labels;
- semantic market colors;
- responsive;
- loading/empty/error.

### Gate F — End-to-end

Critical journey passes Playwright against MockProvider deterministic fixture and, when available, smoke test against real provider read-only market data.

## Required development reporting

- changes;
- migrations;
- commands/tests;
- pass/fail;
- residual risks;
- external credential blockers.

Không đánh dấu complete nếu test chưa chạy.
